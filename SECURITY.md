# Security policy

OrgRec reads untrusted ZIP/VAO archives, media, manifests, and project packages,
and it writes irreplaceable field recordings. Please report path-containment,
archive, resource-exhaustion, malformed-media, privacy, or recording-integrity
issues privately.

The public repository must enable GitHub private vulnerability reporting, or
publish an equivalent monitored security address, before the first release.
Until that channel exists, public release is blocked; do not file exploit
details in a public issue.

Include the affected OrgRec version, macOS version and hardware architecture,
the smallest safe reproducer, expected and observed behavior, and impact. Remove
personal, venue, performer, and unpublished dataset information from reports
unless it is essential and an appropriate private transfer method has been
agreed.

Only the latest public release will be supported after publication. This
release candidate has no security support term until its public reporting route
is enabled.
VAO-format security considerations are documented separately in
[Docs/VAO_SECURITY.md](Docs/VAO_SECURITY.md).
